# Decisions sidecar port evaluation

Evaluated 2026-10-25. **Recommendation: park the port.** This is a documentation-only evaluation; no adapter, credential, account, runtime hook or deployment is added.

The reviewed candidate is [SportsBettingApp PR #27](https://github.com/danteclaird98/SportsBettingApp/pull/27), pinned to [`b8be1aa54a791616a40c52309149c31db28ab28e`](https://github.com/danteclaird98/SportsBettingApp/commit/b8be1aa54a791616a40c52309149c31db28ab28e). Master was inspected at [`719a9e04537360c373534417e7c17df35c8bfb7d`](https://github.com/danteclaird98/sports-betting-master/commit/719a9e04537360c373534417e7c17df35c8bfb7d); unmerged port PRs are not treated as available dependencies.

## What the candidate actually does

Evidence below refers to the pinned [303-line adapter](https://github.com/danteclaird98/SportsBettingApp/blob/b8be1aa54a791616a40c52309149c31db28ab28e/edgeodds/integrations/decisions.py) and [292-line offline test module](https://github.com/danteclaird98/SportsBettingApp/blob/b8be1aa54a791616a40c52309149c31db28ab28e/edgeodds/tests/test_decisions_integration.py).

| Claimed property | Code finding and qualification |
| --- | --- |
| Default-off Python component | Confirmed. `DecisionAdvisor(enabled=False)` is the default (lines 164–185); disabled evaluation returns `DISABLED` before transport (226–227). It is a callable standard-library component, not a service, scheduler or environment-enabled integration. Callers must explicitly supply the transport and enable it. Invalid packet/request-ID inputs can raise local validation errors rather than return an unavailable receipt. |
| One immutable canonical quote | Confirmed. Frozen `EvidencePacket` contains one `NormalizedQuote`, a decision timestamp, and strictly boolean identity/rules flags (43–95). Master already has frozen `NormalizedQuote` and `MarketKey` classes. Canonical JSON/SHA-256 covers the exact market, price, status, native IDs, provenance hash, source/retrieval timestamps and flags. Packet construction validates types and bounds; it does not independently authenticate those caller-supplied flags. |
| Evidence-readiness classification | Confirmed. One choice question returns `SUFFICIENT`, `INSUFFICIENT` or `UNCERTAIN`; result states are `DISABLED`, `ADVISORY` and `UNAVAILABLE`. The prompt expressly prohibits profitability assessment and action authorization (245–249). This is neither a win probability nor a calibrated readiness guarantee. |
| Fixed-origin OpenAI transport | Confirmed in `OpenAIDecisionsTransport` (122–161): a single HTTPS connection to `api.openai.com`, POST `/v1/decisions`, Bearer key, no redirect following or automatic retry. The host/path are not configurable from packet text. The advisor also accepts an injected transport, so the fixed-origin restriction applies to the supplied HTTP implementation. The code pins model alias `gpt-6-luna`; it does not establish a dated immutable model snapshot or prove live endpoint entitlement. |
| Locally bound request/packet receipts | Confirmed with a qualification. The question name hashes request ID plus packet hash, and the answer must echo that question name. `DecisionResult` retains request ID, packet hash, adapter/schema versions, observed model, input-token usage and local evidence references (98–111, 217–249). `evidence_refs` derive from the input source hash, not provider-generated citations. There is no native echoed packet hash, signed provider attestation, or durable receipt store. |
| Strict schema checks | Confirmed for required semantics (277–303): exact expected model alias; one answer; matching question name; supported answer/choice; finite nonboolean confidence; three unique allowed probability entries summing to one; nonnegative integer `usage.input_tokens`. Refusals become unavailable. This is not a closed JSON schema: extra fields are allowed, other usage subfields are not validated, and there is no minimum-confidence threshold or confidence/distribution consistency check. Low confidence alone does not force abstention. |
| Sanitized failures | Confirmed on evaluation/HTTP paths: fixed categories replace auth, rate-limit, network, malformed-response and unknown exception details; provider error bodies are not returned; transport repr redacts the key. Bad clocks and temporal evidence return unavailable without inference. No raw-body logger or persistence is implemented. |
| Bounded calls and payloads | Confirmed with limits. Default instance budget is one transport call; configurable range is 1–100. The supplied HTTP transport caps encoded request/response bodies at 16 KiB/64 KiB. Default socket-I/O timeout is five seconds, configurable up to 30; late completion is rejected using a monotonic elapsed-time check. This cannot cancel blocking inference or establish nonbilling. These byte caps are not enforced against an arbitrary replacement transport. There is no monetary budget, process-wide deadline, or explicit cache-size bound. |
| Instance-local duplicate suppression | Confirmed. A lock and request-ID-to-packet-hash/result cache serialize evaluation and suppress same-ID submissions, including uncertain failures; reuse with a different packet fails (228–275). Replays recheck temporal validity. Neither cache nor call budget survives restart or spans processes. It does not deduplicate equal packets submitted under new IDs, and new advisor instances do not share a budget. |

`_gates` (187–215) checks decision/retrieval/source clocks, freshness and market status using deterministic `evaluate_freshness`, with zero future tolerance and a default 90-second maximum age. It rejects evidence observed after the decision, checks again after inference, and rejects expired replays. Missing/stale/suspended quotes prevent transport. Identity/rules failures alone can still be sent for advisory classification, but keep `deterministic_ready=False` even if the model says `SUFFICIENT`. That flag describes only this limited local gate set; it is not betting eligibility or model approval.

The source adapter has **no storage path and no storage imports**. Its cache is RAM only. Master has SQLite storage, but that does not supply a durable sidecar receipt contract automatically. [fly.toml](../fly.toml) mounts `/var/data` with `EDGEBOARD_DB=/var/data/edgeboard.sqlite3` and `EDGEFUSION_DB=/var/data/edgefusion.sqlite3`; the EdgeOdds CLI separately defaults to `~/.edgeodds/edgeodds.sqlite3` unless passed `--db`. There is no reason to add a synchronous Node route or couple ingestion to inference for this evaluation or a standalone shadow library. No AppDeploy dependency is involved.

## Roadmap mismatch and live-trial blockers

Master's approved scope is a different classifier: identify possible source **market-label anomalies** after deterministic normalization reports `MARKET_NAME_REVIEW_REQUIRED`. Its input is supported market ID/family and source/canonical labels, its outcomes are `consistent`, `possible_mismatch`, `unclear`, and it excludes odds, private account data and full provider payloads. It requires explicit offline/shadow invocation and a low-confidence fallback.

PR #27 instead requires an already normalized full quote, includes `decimal_price`, native event/book IDs and timestamps, uses text-string input plus different choices, and has no minimum-confidence policy. [sportradar.normalize](../edgeodds/sportradar.py) skips label-mismatched markets before quote creation, so those skipped markets do not provide the canonical quote required by this adapter. This is not a drop-in implementation of the master roadmap. A future decision must either separately approve the broader quote-readiness scope or implement the narrower label-triage contract; this evaluation changes neither scope nor the roadmap's proposed implementation status.

The primary external blocker is the supplied account state: **no OpenAI key tied to a confirmed organization/project exists yet**. PR #27 also records that target selection never returned confirmed organization/project IDs and that no live request ran. This evaluation does not inspect private keys, create an account/project/key, or claim that offline tests verify entitlement, account billing, rate limits, latency, current API pricing or live compatibility. The pinned source's API-contract document is historical evidence, not a fresh live-service verification.

If a trial is later authorized, `OPENAI_API_KEY` belongs in **Fly secrets for `edgeodds-danteclaird`, server-side only**, never repository files, browser bundles, packets, HTTP responses or logs. The current transport accepts a key string but does not load environment variables, select an organization/project or send organization/project headers. Account/project association must therefore be confirmed separately. A Python invocation can read the injected server environment; master's Node `runtime/sdk.ts` secrets allowlist currently omits `OPENAI_API_KEY`, but expanding that allowlist is not required for a Python-only library and is not part of this evaluation. No Fly secret is set here.

There are code/data blockers beyond credentials. Master's Sportradar normalizer explicitly constructs quotes with `source_updated_at=None` and unknown settlement rules; it never substitutes feed generation or retrieval time. PR #27 rejects missing source clocks before transport, so importing it plus a key would not produce a live readiness trial from those observations. A representative, provenance-backed eligible packet source must be established without inventing timestamps or verification flags. Old archived decision packets also expire under the advisor's current-clock gate; injected historical clocks support offline fixtures, not proof of current live readiness.

Before a live trial, resolve the scope mismatch, confirm the account/project and endpoint access, define labeled success criteria, and retain sanitized receipts plus request/time/cost accounting across invocations. A timeout or restart must not authorize resubmission of an uncertain potentially billed request. None of this blocks deterministic EdgeOdds ingestion or the separate app launch.

## Authority and validation evidence

Classification **cannot grant betting eligibility in this design**. Neither `choice`, confidence nor `deterministic_ready` supplies missing facts, clears `MARKET_NAME_REVIEW_REQUIRED`, changes aliases/market identity, verifies settlement rules, changes quotes, approves a model or authorizes a wager. The candidate has no imports or calls to storage, execution, agent routing or wager analysis. Master [ingestion.py](../edgeodds/ingestion.py) keeps observations `analysis_eligible=False`, leaves model probability/EV unavailable, and marks EdgeBoard imports unqualified; [edgeboard_contract](../edgeodds/integrations/edgeboard.py) preserves `read_only=True` and `execution=DISABLED`. The normalizer, identity/rules/freshness checks and downstream model/risk gates remain authoritative under the [master roadmap](EDGEODDS_DECISIONS_INTEGRATION_ROADMAP.md). Any future wiring must preserve that one-way advisory boundary, HOLD artifacts and unchanged `edgeodds.edgeboard.v1` output.

The pinned candidate was tested in its **own detached SportsBettingApp checkout**, with no candidate code copied into master: `python3 -m unittest edgeodds.tests.test_decisions_integration -v` passed **18/18**, and `python3 -m unittest discover -s edgeodds/tests` passed **158/158**. Tests inject fake transports/clock and mock HTTPS; no live inference or real key was used. Master's unchanged EdgeOdds suite separately passed **140/140**. Byte comparison confirmed all existing EdgeOdds Python dependencies and fixtures match. These checks establish source behavior and a low dependency cost, not a completed master port or live usefulness. This draft changes one Markdown file only; no app build is claimed necessary for that documentation change.

## Recommendation

**Park it.** Close SportsBettingApp PR #27 with a pointer to this evaluation draft, retaining its pinned commit in history, and revisit only when a confirmed OpenAI organization/project and server-side key make a bounded trial possible and the scope is agreed. Although the reusable library is only two files / 595 Python lines and needs no dependency migration, porting it now would add an unused second classifier contract while leaving the scope, evidence-source and durable trial controls unresolved. Keep deterministic validation and HOLD behavior authoritative; do not port code, broaden the existing roadmap silently, or merge this evaluation automatically.
